Проект: «Размерно»  
Версия: 1.1 draft  
Статус: рабочий Source of Truth по визуализации и 3D-интерфейсу  
Дата: 2026-06-25  

---

# 1. Назначение тома

Том III описывает визуальный слой продукта «Размерно»: Three.js-сцену, режимы отображения, взаимодействие пользователя с моделью, визуальную логику точной настройки, fallback-режимы, требования к качеству, производительности и связи с остальными подсистемами.

Three.js в «Размерно» — не декоративный preview. Это основной рабочий интерфейс, через который пользователь воспринимает мебель, выбирает элементы, понимает конструкцию и выполняет точную настройку.

---

# 2. Роль Three.js в продукте

Three.js должен быть главным визуальным и интерактивным интерфейсом конструктора.

Панель управления помогает пользователю вводить параметры и выполнять быстрые настройки, но именно 3D-сцена должна создавать ощущение, что пользователь действительно собирает мебель.

Главное правило:

> Пользователь работает с мебелью, а не с формой параметров.

---

# 3. Философия 3D-интерфейса

## 3.1 Реалистичность вместо технической схемы

3D-модель должна быть максимально реалистичной в рамках производительности браузера.

Она не должна выглядеть как инженерная CAD-модель или технический чертёж.

Пользователь должен видеть красивую, понятную и современную мебель.

## 3.2 Скрытие production details

В клиентской 3D-сцене нельзя показывать:

- присадку;
- отверстия;
- карты сверления;
- кромку как технический слой;
- пазы;
- внутренние production warnings;
- Basis JSON;
- технологические отметки.

## 3.3 Простота взаимодействия

Любое взаимодействие со сценой должно быть понятным без обучения.

Если пользователь выбирает секцию или панель, система должна визуально объяснять, что выбрано и какие действия доступны.

## 3.4 Визуальная уверенность

3D должен снижать страх ошибки:

- пользователь видит, что собирает;
- понимает пропорции;
- видит материалы;
- видит наполнение;
- видит фасады;
- понимает, как мебель будет собираться.

---

# 4. Режимы сцены

В продукте должно быть три основных режима:

1. Чистый 3D.
2. 3D Static.
3. Exploded View.

Эти режимы решают разные пользовательские задачи и не должны смешиваться в один перегруженный интерфейс.

---

# 5. Режим «Чистый 3D»

## 5.1 Назначение

Режим нужен для визуального восприятия мебели.

Пользователь оценивает:

- форму;
- материалы;
- фасады;
- пропорции;
- общий внешний вид.

## 5.2 Что показывается

- корпус;
- фасады;
- опоры;
- полки, если они видны;
- ящики, если они открыты или отображаются как часть наполнения;
- штанги;
- ручки;
- общие декоративные материалы.

## 5.3 Что не показывается

- размеры;
- технические подписи;
- производственные элементы;
- отверстия;
- присадка;
- кромка;
- warning-коды;
- служебные overlay.

## 5.4 Поведение камеры

Пользователь может:

- вращать модель;
- приближать;
- отдалять;
- осматривать изделие.

Камера не должна мешать восприятию мебели.

## 5.5 Инварианты

- модель не перегружена текстом;
- сцена выглядит современной;
- пользователь не видит production details;
- визуал соответствует выбранным материалам.

---

# 6. Режим «3D Static»

## 6.1 Назначение

3D Static — режим для работы с размерами и точной настройкой.

Он отличается от чистого 3D тем, что допускает интерфейсные элементы поверх модели:

- размеры;
- выделение секций;
- выбор панелей;
- активные зоны;
- локальные controls;
- подсветка элементов.

## 6.2 Что делает пользователь

В этом режиме пользователь может:

- выбрать секцию;
- выбрать отсек;
- выбрать панель;
- изменить материал панели;
- добавить полку;
- задать расстояние полки от нижней панели;
- добавить/убрать наполнение;
- проверить размеры.

## 6.3 Размеры

Размеры должны показываться понятно и не перегружать сцену.

Не нужно показывать все возможные размеры одновременно.

Показываются только те размеры, которые важны в текущем контексте.

## 6.4 Локальные действия

После выбора элемента может появляться локальное меню действий.

Примеры:

- добавить полку;
- добавить ящик;
- добавить штангу;
- изменить материал;
- убрать фасад;
- включить фасад;
- удалить элемент.

## 6.5 Инварианты

- Static Mode не является техническим чертежом.
- Пользователь не видит присадку и кромку.
- Все изменения проходят validation.
- Все изменения отражаются в pricing и production model.

---

# 7. Режим «Exploded View»

## 7.1 Назначение

Exploded View нужен для понимания конструкции и сборки.

Он помогает пользователю увидеть, из каких частей состоит мебель, и почему её можно собрать самостоятельно.

## 7.2 Что показывается

- корпусные панели;
- фасады;
- полки;
- ящики;
- опоры;
- основные элементы наполнения.

## 7.3 Что не показывается

- присадка;
- технические координаты;
- Basis-элементы;
- внутренние production warnings.

## 7.4 Продуктовое значение

Exploded View поддерживает одно из главных обещаний продукта:

> Сборка должна быть понятной.

Это не инженерная документация, а визуальное объяснение.

## 7.5 Инварианты

- Exploded View всегда отдельный режим.
- Он не должен перегружать пользователя техническими деталями.
- Он должен усиливать доверие к самостоятельной сборке.

---

# 8. Выбор объектов

## 8.1 Что можно выбирать

Пользователь может выбирать:

- изделие;
- секцию;
- отсек;
- панель;
- фасад;
- полку;
- ящик;
- штангу;
- опору.

## 8.2 Уровни выбора

Выбор должен быть иерархичным:

```text
Изделие
→ секция
→ отсек / зона
→ конкретный элемент
→ действие
```

## 8.3 Почему нужна иерархия

Без иерархии пользователь быстро потеряется в сложной модели.

Система должна помогать понимать, где пользователь находится и что именно он редактирует.

## 8.4 Визуальное состояние выбора

Минимальные состояния:

- normal;
- hover;
- selected;
- editing;
- disabled.

## 8.5 Инварианты

- выбранный объект всегда визуально понятен;
- недоступные действия не отображаются как активные;
- выбор объекта не раскрывает производственную сложность.

---

# 9. Подсветка и overlays

## 9.1 Подсветка

Подсветка должна быть спокойной, аккуратной и не разрушать реалистичность материала.

Она должна помогать, а не превращать сцену в SaaS-dashboard.

## 9.2 Размерные линии

Размерные линии используются в Static Mode.

Они не используются в чистом 3D.

## 9.3 Локальные controls

Controls появляются только в контексте выбранного объекта.

Нельзя показывать слишком много controls одновременно.

## 9.4 Правило минимальной достаточности

На сцене должно быть только то, что нужно для текущего действия.

---

# 10. Камера и управление

## 10.1 Desktop

На desktop:

- вращение мышью;
- масштабирование колесом;
- панорамирование при необходимости.

## 10.2 Mobile

На mobile:

- вращение одним пальцем;
- масштабирование двумя пальцами;
- панорамирование двумя пальцами или жестом, если это не конфликтует с интерфейсом.

## 10.3 Вид сверху / сбоку

В основном режиме пользователь управляет камерой вручную.

Если в будущем появятся preset-views, они не должны заменять свободное управление.

## 10.4 Инварианты

- камера не должна ломать ориентацию пользователя;
- модель всегда должна оставаться в видимой зоне;
- mobile gestures не должны конфликтовать с bottom sheet / панелью.

---

# 11. Материалы в 3D

## 11.1 Принцип

Материалы должны соответствовать выбранным материалам в конструкторе.

Если пользователь меняет материал изделия, фасада или отдельной панели, 3D должен сразу это показать.

## 11.2 Реалистичность

Материалы должны выглядеть как мебельные декоры, а не как плоские заливки.

## 11.3 Направление текстуры

3D должен учитывать правило направления текстуры:

- ширина больше высоты → горизонтально;
- иначе вертикально;
- ХДФ без направления.

## 11.4 Panel-level override

Если пользователь изменил материал отдельной панели, 3D должен отобразить именно эту панель с новым материалом.

---

# 12. Производительность

## 12.1 Приоритеты

Приоритеты:

1. стабильность;
2. визуальное качество;
3. FPS;
4. дополнительные эффекты.

## 12.2 Auto quality

Качество должно подбираться автоматически.

Пользователь не должен думать о technical quality mode.

## 12.3 Что нельзя делать

Нельзя добавлять визуальные эффекты, которые ухудшают стабильность основного сценария.

## 12.4 Mobile

На mobile нужно сохранить и качество, и стабильность.

Если устройство слабое, система должна упрощать рендер без разрушения пользовательского сценария.

---

# 13. Fallback

## 13.1 Назначение

Fallback нужен, если WebGL недоступен или работает нестабильно.

## 13.2 Требования

Fallback должен позволять:

- увидеть изделие;
- задать размеры;
- выбрать материалы;
- настроить базовое наполнение;
- отправить валидную заявку.

## 13.3 Режимы fallback

Fallback должен поддерживать:

- статичное отображение;
- понимание размеров;
- базовую визуализацию конструкции;
- если возможно — упрощённый exploded representation.

## 13.4 Инвариант

Отсутствие WebGL не должно блокировать заказ.

---

# 14. Связь с конструктором

Three.js получает состояние из конструктора.

Three.js отправляет пользовательские действия обратно в состояние конструктора.

Three.js не является самостоятельным source of truth.

Source of truth:

- constructor state;
- production model;
- saved configuration.

## Примеры

- пользователь выбрал панель → constructor state updates selectedPanel;
- пользователь изменил материал панели → constructor state updates panel material override;
- пользователь добавил полку → constructor state updates filling;
- production model пересчитывается;
- pricing пересчитывается;
- 3D обновляется.

---

# 15. Связь с Production JSON

3D не формирует Production JSON напрямую.

Но действия в 3D должны быть полностью отражаемы в Production JSON.

Если действие нельзя корректно выразить в production model, оно не должно быть валидным действием.

---

# 16. Связь с Pricing

3D-сцена не считает цену.

Но любое действие через 3D, влияющее на конфигурацию, должно запускать pricing recalculation.

Примеры:

- добавление секции;
- изменение материала панели;
- добавление ящика;
- выбор фасада;
- изменение опор.

---

# 17. Связь с личным кабинетом

В личном кабинете пользователь может видеть сохранённый проект.

Клиентское представление проекта может использовать 3D/preview, но без production details.

---

# 18. Инварианты визуализации

1. Three.js — основной рабочий интерфейс.
2. Three.js не является source of truth.
3. Пользователь не видит production details.
4. Чистый 3D не перегружен overlay.
5. Static Mode используется для размеров и точной настройки.
6. Exploded View используется для понимания сборки.
7. Fallback не блокирует заказ.
8. Материалы соответствуют выбранной конфигурации.
9. Panel-level material override отображается визуально.
10. Любое действие в 3D синхронизируется с constructor state.
