# Razmerno Product & Engineering Specification (RPES)

Версия: 1.0 draft  
Статус: рабочий Source of Truth проекта «Размерно»  
Дата: 2026-06-25  

## Назначение

RPES — главный документ проекта «Размерно». Он фиксирует актуальные продуктовые, UX, инженерные, производственные и архитектурные решения.

RPES не заменяет исходный код, backlog или тесты. Он задаёт правила, по которым должны формироваться backlog, архитектурные решения, задачи для Cursor/Codex и дальнейшая разработка.

## Приоритет источников

При конфликте источников используется следующий порядок:

1. RPES.
2. Актуальный backlog.
3. Код.
4. Исторические документы.
5. Старые сообщения/чаты.

Если старое решение конфликтует с новым решением, зафиксированным в RPES, актуальным считается решение из RPES.

## Правило разработки

Любая крупная задача должна ссылаться на соответствующий том RPES.

Процесс:

```text
Идея
→ обсуждение
→ фиксация в RPES
→ обновление backlog
→ реализация
→ QA
→ синхронизация evidence
```

## Дополнение v1.1 — решения по клиентскому пути, секциям, SKU, Supabase и v4

В этой версии дополнительно зафиксированы решения:

- при изменении общего размера изделия пользователь выбирает способ перераспределения изменения: равномерно, сохранить секции или вручную;
- секции могут добавляться справа и сверху;
- вертикальное добавление работает как новая строка/уровень, но пользователь позже может расширять верхнюю секцию независимо от нижней;
- глубина секций в одном изделии пока всегда одинаковая;
- пользователь выбирает производителя фурнитуры, но не конкретные SKU;
- SKU-подбор фурнитуры выполняется системой после наполнения Supabase-каталога;
- конструктор должен предотвращать ошибочные варианты до выбора;
- высота между полками не менее 300 мм;
- материал в конструкторе должен существовать в Supabase;
- production fallback по отсутствующему материалу запрещён как принцип;
- Production v4 должен заменить v3 полностью после controlled migration; долгосрочная поддержка v3+v4 не планируется.
