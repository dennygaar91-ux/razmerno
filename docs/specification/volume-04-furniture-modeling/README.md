# 1. Назначение тома

Том IV описывает правила построения мебели в «Размерно».

Это не описание UI и не документация по конкретным React/Three.js-компонентам. Это производственно-продуктовая спецификация того, как мебель должна моделироваться: из каких частей состоит изделие, как строятся секции, панели, фасады, полки, ящики, материалы, опоры и ограничения.

Главная цель тома:

> Зафиксировать правила моделирования так, чтобы конструктор, Three.js, Pricing, Production JSON, Admin и Basis manual plan строили одну и ту же мебель.

---

# 2. Роль моделирования мебели

Моделирование мебели — центральный инженерный слой проекта.

Конструктор позволяет пользователю управлять мебелью, Three.js показывает результат, Pricing считает стоимость, но именно furniture modeling определяет, что является корректной мебелью.

Если интерфейс позволяет действие, но furniture modeling не может построить валидную модель — действие не должно считаться валидным.

---

# 3. Типы мебели MVP

Для MVP поддерживаются три типа мебели:

1. Шкаф.
2. Тумба.
3. Комод.

Другие виды мебели относятся к post-MVP.

## Почему эти три типа

Они позволяют покрыть базовый ассортимент и одновременно проверить ключевые производственные сценарии:

- вертикальный корпус;
- фасады;
- полки;
- ящики;
- опоры;
- разные правила верхней панели;
- разные сценарии наполнения.

---

# 4. Общие производственные правила

## 4.1 Корпус

Корпус всех изделий выполняется только из ЛДСП 16 мм.

Это правило является обязательным для MVP.

## 4.2 Фасады

Фасады могут быть:

- ЛДСП 16 мм;
- МДФ 18 мм.

Выбор зависит от материала фасада.

## 4.3 Задняя стенка

Задняя стенка выполняется из ХДФ.

Актуальное правило толщины:

- ХДФ 3 мм.

## 4.4 Дно ящика

Дно ящика выполняется из ХДФ.

Актуальное правило толщины:

- ХДФ 3 мм.

## 4.5 Кромка

Кромка выполняется по кругу.

Актуальные правила:

- корпусные детали, полки, drawer-box: 1 мм по всем сторонам;
- фасады и drawer-front: 2 мм по всем сторонам;
- ХДФ без кромки.

## 4.6 Зазоры фасадов

Зазор фасада:

- 1,5 мм со всех сторон.

Для парных фасадов:

- между фасадами общий зазор 3 мм.

## 4.7 Полки

Внутренние полки должны быть утоплены на 30 мм относительно лицевой части боковин.

Это правило нужно для корректной работы фасадов, визуальной аккуратности и предотвращения конфликта наполнения с дверями.

## 4.8 Высота изделия

Высота изделия включает высоту опор.

```text
высота изделия = высота корпуса + высота опор
```

Это правило обязательно для конструктора, Production JSON, Pricing, Three.js, личного кабинета и админки.

# 5. Различия типов мебели

## 5.1 Шкаф

Для шкафа:

- боковые стенки стоят на дне;
- верхняя панель располагается между боковинами;
- допускаются полки, ящики, штанги;
- опоры могут быть выбраны по правилам support policy;
- фасады могут быть одиночными или парными.

## 5.2 Тумба

Для тумбы:

- боковые стенки стоят на дне;
- верхняя панель располагается сверху боковин;
- верхняя панель больше корпуса на 1,5 мм спереди и по бокам;
- это нужно, чтобы кромка перекрывала торцы;
- допускаются фасады, полки и ящики.

## 5.3 Комод

Для комода:

- боковые стенки стоят на дне;
- верхняя панель располагается сверху боковин;
- верхняя панель больше корпуса на 1,5 мм спереди и по бокам;
- основной сценарий наполнения — ящики;
- drawer-front считается фасадной деталью.

## 5.4 Инвариант различий

Нельзя применять правило верхней панели шкафа к тумбе или комоду.

Нельзя применять правило верхней панели тумбы/комода к шкафу.

# 6. Секционная модель

## 6.1 Принцип

Мебель должна моделироваться через секции.

Секция — базовый строительный блок изделия.

Пользователь может создавать изделие не только через общий размер, но через структуру секций.

## 6.2 Ограничения секции

Актуальные ограничения:

- ширина: 200–900 мм;
- высота: 200–2000 мм;
- глубина: 150–900 мм.

## 6.3 Добавление секций

Секции могут добавляться:

- влево;
- вправо;
- вверх.

Это означает, что модель должна быть готова не только к горизонтальному делению, но и к вертикальной модульной структуре.

## 6.4 Почему секции важны

Секции позволяют:

- избежать понятия «нестандартный размер»;
- контролировать производственные ограничения;
- ограничивать максимальную ширину;
- упростить pricing;
- сделать модель воспроизводимой;
- упростить Basis manual plan.

## 6.5 Открытая терминология

Термины «секция», «отсек» и «зона» пока требуют финального закрепления.

Рабочая логика:

- секция — крупный блок мебели;
- отсек — внутренняя часть секции;
- зона — интерактивная область в 3D.

# 7. Панели

## 7.1 Основные роли панелей

В модели должны поддерживаться роли:

- боковина левая;
- боковина правая;
- дно;
- верх;
- полка;
- вертикальная перегородка;
- задняя стенка;
- фасад;
- drawer-front;
- drawer-side;
- drawer-back;
- drawer-bottom;
- цоколь / опорный элемент, если используется.

## 7.2 Панель как производственная единица

Каждая панель должна иметь:

- роль;
- размеры;
- материал;
- толщину;
- направление текстуры;
- кромку, если применимо;
- связь с изделием/секцией;
- включение в production JSON.

## 7.3 Направление текстуры

Правило:

- если ширина панели больше высоты — направление горизонтальное;
- иначе вертикальное;
- ХДФ без направления.

## 7.4 Материал отдельной панели

Пользователь может менять материал отдельной панели в режиме точной настройки.

Это должно отражаться в:

- Three.js;
- Pricing;
- Production JSON;
- личном кабинете;
- админке.

# 8. Фасады

## 8.1 Роль фасада

Фасад — видимая лицевая деталь мебели.

Фасад влияет на:

- внешний вид;
- фурнитуру;
- ручки;
- push-to-open;
- pricing;
- production JSON;
- Basis manual plan.

## 8.2 Материалы фасадов

Допустимо:

- ЛДСП 16 мм;
- МДФ 18 мм.

## 8.3 Зазоры

Каждый фасад имеет зазор 1,5 мм со всех сторон.

Парные фасады имеют общий центральный зазор 3 мм.

## 8.4 Drawer-front

Drawer-front считается фасадной деталью.

На drawer-front распространяются правила:

- фасадной толщины;
- фасадной кромки;
- фасадных материалов;
- ручек / push-to-open;
- визуального отображения.

## 8.5 Opening modes

Актуальные режимы:

- с ручками;
- без ручек / push-to-open;
- скрытая ручка, если будет реализована.

Если пользователь выбирает ручки — используется фурнитура с доводчиками.

Если пользователь выбирает без ручек — используется push-to-open.

---

# 9. Полки

## 9.1 Материал

Полки выполняются из ЛДСП 16 мм.

## 9.2 Положение

Полки внутри мебели утоплены на 30 мм относительно лицевой части боковин.

## 9.3 Добавление

Пользователь выбирает секцию и указывает расстояние от нижней панели.

## 9.4 Валидация

Система должна проверять:

- помещается ли полка;
- не конфликтует ли с фасадом;
- не конфликтует ли с ящиком;
- соблюдены ли минимальные расстояния.

## 9.5 Фурнитура

Полки устанавливаются на усиленных полкодержателях.

Конкретные SKU будут определены позже.

---

# 10. Ящики

## 10.1 Статус

Правила ящиков ещё требуют отдельной инженерной детализации.

Уже зафиксировано:

- drawer-front — фасадная деталь;
- дно ящика — ХДФ 3 мм;
- направляющие скрытого монтажа;
- два пользовательских варианта:
  - с доводчиками;
  - push-to-open.

## 10.2 Что нужно определить

- точные размеры боковин;
- задник ящика;
- глубина ящика;
- выбор длины направляющих;
- SKW = LW - 42;
- LT = NL + 5;
- правила полезного объёма;
- ограничения по толщине;
- правила установки дна.

## 10.3 Связь с будущими задачами

Ящики не должны финализироваться без отдельного Drawer Engineering Layer.

---

# 11. Штанги

## 11.1 Роль

Штанга используется для шкафа и относится к наполнению.

## 11.2 Ограничения

Штанга должна проверяться на совместимость:

- с шириной секции;
- с глубиной секции;
- с высотой зоны;
- с фасадами и полками.

## 11.3 Production

Штанга должна попадать в production JSON как элемент фурнитуры/наполнения.

---

# 12. Опоры

## 12.1 Типы

Актуальные типы:

1. Без опоры — изделие устанавливается на дно.
2. Регулируемые ножки 60 мм.
3. Регулируемые ножки 100 мм.
4. Металлическая регулируемая опора с шипами.

## 12.2 Правило высоты

Высота опор входит в общую высоту изделия.

## 12.3 Матрица количества

Актуальная v4 policy:

- ширина до 1200 мм — 4 опоры;
- 1201–2400 мм — 6 опор;
- 2401–3600 мм — 8 опор;
- больше 3600 мм — требует проверки.

## 12.4 Placement

Опоры размещаются симметрично по передней и задней линиям.

# 14. Валидация модели

Модель валидна, если:

- все секции в допустимых размерах;
- все панели имеют допустимый материал;
- все фасады имеют корректные зазоры;
- все элементы помещаются;
- нет конфликтов наполнения;
- price может быть рассчитан;
- production JSON может быть сформирован;
- Basis manual plan может быть подготовлен.

Ошибочная модель не может быть отправлена как заявка.

# 15. Связь с Pricing

- площадь материалов;
- кромку;
- фурнитуру;
- количество панелей;
- фасады;
- опоры;
- упаковку.

# 20. Дополнительные правила моделирования v1.1

## 20.1 Координатная система

Для моделирования и формирования JSON используется фундаментальное правило:

> координаты начинаются с левого нижнего дальнего угла.

Это правило должно применяться одинаково в:

- секционной модели;
- Three.js;
- Production JSON;
- Basis manual plan;
- validation;
- будущей карте присадки.

## 20.2 Добавление секций сверху

Секция может быть добавлена сверху.

При этом верхняя секция может иметь собственную ширину, которая не обязана совпадать с шириной нижней секции.

Это решение требует осторожной модели координат и assembly-связей, потому что структура перестаёт быть простой равномерной сеткой.

## 20.3 Одинаковая глубина секций

До отдельного решения глубина всех секций внутри изделия одинаковая.

Разная глубина запрещена в MVP/Release v1.

## 20.4 Минимальная высота между полками

Минимальная высота между полками — 300 мм.

Система не должна позволять создать зону между полками меньше 300 мм.

## 20.5 Ящики шире 600 мм

Если ящик шире 600 мм, комплект должен учитывать синхронизатор для ящиков.

Это правило относится к будущему Drawer Engineering Layer и SKU Mapping Layer.

## 20.6 Направляющие скрытого монтажа

На текущем этапе используются только направляющие скрытого монтажа.

Другие типы направляющих не входят в MVP/Release v1.

## 20.7 Правило длины направляющей

Длина направляющей выбирается автоматически.

Доступные длины:

- 250 мм;
- 300 мм;
- 350 мм;
- 400 мм;
- 450 мм;
- 500 мм;
- 550 мм.

Правило:

```text
глубина секции >= длина направляющей + 50 мм
```

Между задней стенкой и направляющей должен оставаться зазор не менее 50 мм.

## 20.8 Push-to-open и доводчики

Для направляющих используется один базовый тип скрытого монтажа, но разные механизмы:

- вариант с доводчиком: пользователь тянет фасад/ручку, закрывание с доводчиком;
- вариант push-to-open: используется толкатель + доводчик.

## 20.9 Петли и фасады

На MVP/Release v1 используются только накладные фасады.

Распашные фасады возможны для шкафа, тумбы и комода, но для тумбы и комода это действие должно быть доступно через режим «Точная настройка».

Поддерживаются:

- одиночные фасады;
- парные фасады.

UX для выбора одиночного/парного фасада требует отдельной проработки.

## 20.10 Выбор производителя фурнитуры

Пользователь выбирает производителя фурнитуры, но не конкретную модель.

Система сама подбирает конкретную фурнитуру по правилам после наполнения Supabase SKU-каталога.

Это правило применяется к:

- петлям;
- направляющим;
- полкодержателям;
- опорам;
- push-to-open;
- ручкам, если применимо.

## 20.11 Долг: автоматический подбор фурнитуры

После заполнения Supabase SKU-каталога нужно реализовать слой автоматического подбора всей фурнитуры.

Этот слой должен учитывать:

- выбранного производителя;
- тип мебели;
- тип фасада;
- наличие ручек;
- push-to-open;
- размеры секции;
- ширину ящика;
- глубину секции;
- вес/размер фасада, если потребуется;
- производственные ограничения.
