\# Task 001 — Architecture Audit



\## Цель



Провести архитектурный аудит актуального проекта «Размерно» после загрузки последней версии в GitHub.



\## Важно



На этом этапе ничего не менять в коде.



Только анализ.



\## Нужно проверить



1\. Структуру папок.

2\. Большие файлы.

3\. Дублирующиеся компоненты.

4\. Дублирующуюся бизнес-логику.

5\. Устаревшие legacy-зоны.

6\. Конфликты между старым конструктором и новым Constructor3D.

7\. Состояние styles/.

8\. Состояние tests/.

9\. Состояние scripts/.

10\. Риски для дальнейшей разработки агентом.



\## Отдельно проверить



\- src/static-pages/constructor/

\- src/constructor/

\- src/pricing/

\- src/styles/

\- api/

\- tests/

\- scripts/



\## Результат



Создать документ:



docs/audits/architecture-audit-001.md



В документе должны быть:



1\. Executive summary.

2\. Карта проекта.

3\. Список проблем P0/P1/P2/P3.

4\. Список больших файлов.

5\. Список дублей.

6\. Список зон, которые нельзя трогать без разрешения.

7\. Рекомендованный план декомпозиции.

8\. Риски.

9\. Следующие задачи для агента-разработчика.



\## Проверки



Код не менять.



Запустить только:



npm run typecheck

npm run build



Если проверки не проходят — зафиксировать ошибки в отчёте, но не исправлять.
