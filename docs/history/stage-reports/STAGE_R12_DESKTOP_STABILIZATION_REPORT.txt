Stage R12 — desktop constructor emergency stabilization
Дата: 2026-06-09

Вопросы перед стартом Stage R12:
- Блокирующих вопросов не было: пользователь уже утвердил направление — диагностика 3D, честный 2D fallback, desktop-first, без mobile, без изменения pricing/order/backend.
- Решений пользователя на этом этапе не требовалось.

Что планировалось:
1. Начать с безопасного исправления критичных UX/layout-багов конструктора.
2. Не трогать pricing, заявки, checkout-flow, API, backend, Supabase, order export.
3. Сделать 3D/WebGL fallback честнее: убрать ложное состояние, где 2D выглядит как 3D.
4. Сократить визуальную длину левой панели и убрать дублирование ошибок.
5. Стабилизировать desktop layout: sidebar не должен растягивать всю страницу бесконечной колонкой.
6. Уменьшить шум шага «Наполнение»: спрятать часть точной настройки и вторичных ошибок.

Что сделано:
1. Добавлена диагностика WebGL:
   - новый тип WebGLDiagnostics;
   - статус checking / available / unavailable;
   - причина unavailable теперь сохраняется в reason;
   - проверка WebGL больше не выглядит как финальная недоступность до окончания client-side detection.
2. ConstructorScene теперь получает webglDiagnostics и отличает:
   - проверку WebGL;
   - ручной 2D;
   - реальную недоступность WebGL;
   - ошибку Three.js runtime.
3. Fallback-note стал честнее:
   - manual 2D больше не показывает тревожную плашку;
   - при webgl-unavailable показывается причина;
   - при checking показывается временный нейтральный статус.
4. Упрощён ConstructorValidationPanel:
   - вместо стены ошибок показывается одна главная ошибка текущего шага;
   - остальные ошибки доступны через компактную кнопку «Ещё …»;
   - valid-состояние стало компактным.
5. Упрощён шаг «Наполнение»:
   - «Отсеки по высоте» перенесены в точную настройку;
   - список нескольких fill-ошибок скрыт из обычного режима;
   - блок «Фасады» сокращён;
   - карточки выбора секции/отсека стали компактнее через CSS.
6. Добавлен emergency CSS-слой Stage R12:
   - desktop shell шире и стабильнее;
   - левая панель ограничена по высоте viewport;
   - содержимое шага внутри sidebar скроллится, а кнопки действий остаются внизу панели;
   - scene workbar разложен по сетке;
   - 2D blueprint очищен от лишней декоративности;
   - material-note вынесен визуально аккуратнее;
   - validation compact styles добавлены отдельно.

Что не сделано на этом Stage:
1. Полностью не переписан 2D Drawing Renderer — сделан только emergency visual cleanup.
2. Полностью не пересобран desktop shell в новую компонентную архитектуру — только стабилизация без риска для логики.
3. Реальный браузерный runtime Three.js не подтверждён через Playwright, потому что в sandbox отсутствует Chromium binary.
4. Checkout не трогался.
5. Mobile не трогался.

Риски:
1. CSS-файл уже содержит много исторических override-слоёв. Stage R12 добавляет безопасный финальный слой, но долгосрочно нужен cleanup после стабилизации визуала.

3. Если Three.js падает из-за runtime-ошибки, в sandbox это нельзя подтвердить без браузера; нужно получить console error из локального запуска.
