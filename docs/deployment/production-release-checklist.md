# Production release checklist

## 1. До деплоя

### Код

- [ ] Рабочая ветка синхронизирована с актуальным архивом.
- [ ] Выполнено `npm install`.
- [ ] Выполнено `npm run production:preflight`.
- [ ] Build проходит без ошибок.
- [ ] `npm audit --audit-level=moderate` проходит без уязвимостей.

### Env в Vercel

Server env:

- [ ] `ORDER_MANAGER_EMAIL`
- [ ] `RESEND_API_KEY`
- [ ] `MAIL_FROM`
- [ ] `ALLOWED_ORIGINS=https://razmerno.ru`
- [ ] `SUPABASE_URL`
- [ ] `SUPABASE_SERVICE_ROLE_KEY`
- [ ] `UPSTASH_REDIS_REST_URL`
- [ ] `UPSTASH_REDIS_REST_TOKEN`

Client env:

- [ ] `VITE_YM_ID`

Optional env:

- [ ] `VITE_FORCE_SVG_VIEWER=0`
- [ ] `VITE_ENABLE_PRODUCTION_DEBUG=0`
- [ ] `VITE_ANALYTICS_DEBUG=0`
- [ ] `VITE_USE_MOCK_API` не включён.

### Supabase

- [ ] Таблица `orders` создана.
- [ ] Выполнена миграция `db/orders-layout-migration.sql`.
- [ ] В таблице есть поле `layout jsonb`.
- [ ] RLS/доступы настроены так, чтобы frontend не имел service-role ключа.
- [ ] Service-role key находится только в Vercel server env.
- [ ] Тестовая заявка записывается в БД.

### Resend / email

- [ ] Домен отправки подтверждён.
- [ ] `MAIL_FROM` не использует `onboarding@resend.dev`.
- [ ] Письмо менеджеру приходит.
- [ ] Письмо клиенту приходит.
- [ ] Если письмо клиенту не ушло, заявка всё равно считается успешной для менеджера.
- [ ] Ошибка письма клиенту логируется.

### Домен / routing

- [ ] `https://razmerno.ru` открывается.
- [ ] `https://razmerno.ru/configurator` открывается напрямую.
- [ ] Старая ссылка `#/configurator` редиректится.
- [ ] `vercel.json` содержит rewrites на `/configurator`.

## 2. Ручной smoke-test после деплоя

### Лендинг

- [ ] Главная открывается без белого экрана.
- [ ] Header работает.
- [ ] Якорные ссылки работают.
- [ ] CTA ведёт в конструктор.
- [ ] Мобильная версия не ломает layout.

### Конструктор

- [ ] QuickStart открывается, если тип не выбран.
- [ ] Можно выбрать шкаф/комод/тумбу.
- [ ] Размеры меняются.
- [ ] Цена пересчитывается.
- [ ] 3D отображается.
- [ ] Advanced mode включается.
- [ ] Можно добавить секцию по ширине.
- [ ] Можно добавить отсек по высоте.
- [ ] Можно выбрать полки/ящики/штангу в конкретном отсеке.
- [ ] Выбранный отсек подсвечивается.
- [ ] `+`-маркеры на 3D работают.

### Checkout

- [ ] Телефон обязателен и принимает RU-номер.
- [ ] Email обязателен.
- [ ] Доставка выключена по умолчанию.
- [ ] При включении доставки появляется адрес.
- [ ] Без адреса доставки заявка не отправляется.
- [ ] Согласие на ПДн обязательно.
- [ ] Повторная отправка раньше 30 секунд блокируется.
- [ ] После успешной заявки модель не сбрасывается.
- [ ] Повторное открытие checkout не показывает старый success после закрытия.

### Security

- [ ] Honeypot поле скрыто.
- [ ] API пересчитывает цену на сервере.
- [ ] API отклоняет чужой origin.
- [ ] Rate-limit включён через Upstash.
- [ ] В localStorage не сохраняются PII-заявки.

## 3. Аналитика

- [ ] `VITE_YM_ID` задан.
- [ ] Pageview главной фиксируется.
- [ ] Pageview `/configurator` фиксируется.
- [ ] События выбора типа мебели фиксируются.
- [ ] События checkout отправки фиксируются.
- [ ] Ошибки отправки фиксируются.

## 4. Rollback

Перед публикацией сохранить:

- [ ] Последний рабочий архив проекта.
- [ ] ID/ссылку последнего стабильного Vercel deployment.
- [ ] SQL backup/экспорт заявок Supabase.
- [ ] Список env-переменных без раскрытия секретов.

Если после деплоя критическая ошибка:

1. Откатить Vercel deployment на предыдущий stable.
2. Проверить, что `/api/orders` снова работает.
3. Зафиксировать причину ошибки в `docs/history`.
4. Не менять БД без отдельной миграции/backup.

## 5. Go / No-Go

Запуск разрешён, если:

- [ ] `production:preflight` проходит.
- [ ] Тестовая заявка проходит полный путь.
- [ ] Менеджер получает письмо.
- [ ] Заявка появляется в Supabase.
- [ ] Клиент получает письмо или ошибка клиентского письма логируется.
- [ ] Нет критичных ошибок в консоли браузера.
- [ ] Нет 500 в Vercel logs.
