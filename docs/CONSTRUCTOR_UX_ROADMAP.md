# Размерно — roadmap UX/UI улучшения конструктора

Документ фиксирует поэтапный план улучшения конструктора после design review. Каждый этап внедряется отдельным небольшим PR, чтобы не ломать уже работающую механику.

## Общий порядок

1. Проверка текущего состояния после внедрённых PR.
2. Viewer: визуальная полировка центрального предпросмотра.
3. Динамические инженерные предупреждения.
4. Улучшение левой панели настроек.
5. Улучшение правой панели «Ваш проект».
6. Сохранение и шаринг проекта.
7. Checkout и заявка.
8. Мобильный сценарий.
9. Backend-ready архитектура.
10. Финальная полировка design system.

## Этап 1 — Проверка текущего состояния

Цель: убедиться, что production/deploy содержит последние изменения и нет regressions.

Проверить:

- страница `/constructor` открывается без белого экрана;
- onboarding показывается на первом входе;
- кнопка «Как работает» открывает onboarding повторно;
- stepper показывает завершённые шаги;
- левая панель меняется по шагам;
- viewer не содержит конфликтующих быстрых действий;
- правая панель показывает чеклист;
- checkout открывается в двух шагах;
- выбор материала влияет на preview;
- нет ошибок React в консоли.

## Этап 2 — Viewer

Цель: сделать центральный preview шкафа визуально легче, дороже и понятнее.

Задачи:

- убрать тяжёлую чёрную подложку;
- заменить её на лёгкую размерную систему;
- улучшить CSS-модель шкафа;
- сделать активную секцию заметной, но не агрессивной;
- разделить визуальную роль 3D/2D;
- сохранить текущую механику выбора секций.

Ожидаемый результат: viewer становится главным визуальным центром конструктора, а не технической заглушкой.

## Этап 3 — Инженерные предупреждения

Цель: предупреждать пользователя об ошибках в момент настройки, а не только в правой панели.

Задачи:

- warnings рядом с размерами;
- warnings рядом с наполнением;
- разделить info / recommendation / warning / error;
- раскрытие всех рекомендаций в summary;
- понятные тексты без мебельного жаргона.

## Этап 4 — Левая панель

Цель: превратить левую панель из набора технических кнопок в помощника по сборке шкафа.

Задачи:

- пресеты размеров;
- сценарии наполнения: одежда, бельё, прихожая, коробки;
- более понятные карточки секций;
- снижение плотности;
- подсказки по замерам и ограничениям.

## Этап 5 — Правая панель

Цель: сделать правую панель коммерческим блоком доверия.

Задачи:

- уточнить цену как предварительную;
- раскрытая смета;
- «Комплект» → «Состав комплекта»;
- блок «Что будет после заявки»;
- усиление CTA.

## Этап 6 — Сохранение и шаринг

Цель: дать пользователю возможность вернуться к проекту и отправить ссылку.

Задачи:

- улучшить статус autosave;
- project ID;
- share URL;
- копирование ссылки;
- backend-ready методы save/load/update/share.

## Этап 7 — Checkout и заявка

Цель: довести checkout до реального мебельного бизнес-сценария.

Задачи:

- двухшаговый checkout уже внедрён;
- добавить сборку +10%;
- доставка внутри МКАД 6000 ₽;
- за МКАД 6000 ₽ + 75 ₽/км;
- экран успеха после заявки;
- order payload для backend.

## Этап 8 — Мобильный сценарий

Цель: сделать отдельный мобильный UX, а не просто сжать desktop.

Задачи:

- вертикальный сценарий;
- viewer как collapsible preview;
- sticky bottom CTA;
- итог вместо правой панели;
- увеличить кликабельные зоны.

## Этап 9 — Backend-ready архитектура

Цель: подготовить конструктор к реальному backend-расчёту.

Задачи:

- нормализовать project schema;
- разделить frontend state и backend payload;
- API contracts;
- вынести расчёты из UI;
- Basis JSON export.

## Этап 10 — Design System

Цель: привести интерфейс к единой визуальной системе.

Задачи:

- токены;
- кнопки;
- карточки;
- состояния;
- финальный visual QA.
