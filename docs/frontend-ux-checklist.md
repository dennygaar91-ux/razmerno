# Frontend UX checklist конструктора

Цель: пройти сценарий пользователя целиком и убедиться, что фронт конструктора ощущается как готовый продуктовый pre-MVP.

## 1. Вход в конструктор

Проверить:

- страница открывается без горизонтального развала;
- hero не занимает слишком много места на laptop;
- видны три главные зоны: настройка / viewer / стоимость;
- CTA `В корзину` не конкурирует с основным сценарием.

Статус: частично готово.

## 2. Шаг “Размеры”

Проверить:

- пользователь понимает, с чего начать;
- `+ / −` имеют disabled-состояния;
- значения не выходят за пределы;
- ширина секций понятна;
- предупреждения объясняют, что исправить.

Статус: хорошо, нужен визуальный тест по скриншотам.

## 3. Шаг “Наполнение”

Проверить:

- активная секция очевидна;
- связь левой панели, viewer и карты секций читается;
- presets понятны;
- quick actions не дублируют левую панель слишком шумно;
- штанга объясняет недоступность при малой глубине.

Статус: хорошо, нужен визуальный тест.

## 4. Шаг “Материалы”

Проверить:

- выбранный материал виден сразу;
- карточки материалов не перегружены;
- цена `база / −% / +%` понятна;
- открывание с ручками / без ручек объяснено честно;
- кромка и проверка технологом не выглядят как ошибка.

Статус: хорошо, нужен визуальный тест.

## 5. Viewer

Проверить:

- mockup шкафа не выглядит слишком временно;
- размеры вокруг шкафа не перекрывают модель;
- активная секция подсвечена достаточно заметно;
- карта секций не ломается при 1–6 секциях;
- quick actions не занимают слишком много места на 1366×768.

Статус: средне-хорошо, основной риск — плотность на laptop.

## 6. Правая панель

Проверить:

- стоимость — главный элемент;
- статус проекта понятен;
- смета раскрывается без скачка layout;
- CTA заметен;
- warnings не пугают пользователя.

Статус: хорошо.

## 7. Checkout drawer

Проверить:

- drawer открывается поверх конструктора без визуального конфликта;
- 3 шага оформления читаются;
- ошибки полей понятны;
- success-state выглядит завершённо;
- текст про оплату после проверки технологом понятен.

Статус: хорошо, нужен визуальный тест.

## 8. Сохранение / загрузка

Проверить:

- после сохранения показывается ID проекта;
- последний projectId сохраняется в localStorage;
- загрузка берёт последний projectId;
- очистка удаляет проект, id и metadata;
- badge в hero показывает состояние сохранения.

Статус: улучшено, нужен ручной тест.

## 9. Desktop/laptop

Проверить разрешения:

- 1536×1024;
- 1536×864;
- 1440×900;
- 1366×768.

Статус: CSS-адаптация добавлена, нужен визуальный контроль.

## 10. Что править по скриншотам в первую очередь

1. Если левая панель стала слишком плотной — сокращать тексты и высоты карточек.
2. Если viewer съехал — править `ConstructorViewerPolish.css` и `ConstructorDesktopPass.css`.
3. Если правая панель не помещается — убирать вторичные блоки в summary.
4. Если drawer тяжёлый — сокращать высоты step-блоков.
5. Если визуально всё разностильно — унифицировать border-radius, shadows и font-weight.
