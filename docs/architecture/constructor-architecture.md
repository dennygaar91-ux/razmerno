# Constructor Architecture — «Размерно»

Дата: 2026-06-13
Тип: architecture documentation.

## Цель

Документ описывает архитектурные границы конструктора без изменения кода приложения. Он нужен, чтобы дальнейшая разработка конструктора шла управляемо и без случайного смешения интерфейса, 3D-визуализации, расчета, заявки и производственной логики.

## Product principle

Пользователь не должен ощущать, что заполняет сложную техническую форму. Основной сценарий — собрать мебель как понятный пошаговый конструктор.

## Основные слои конструктора

### UI shell

Отвечает за шаги, панели управления, кнопки, статусы и подсказки. Не должен содержать самостоятельные правила расчета стоимости.

### Constructor state

Отвечает за размеры, тип мебели, секции, зоны, наполнение, фасады, материалы и выбранные опции заявки. State должен быть предсказуемым, тестируемым и сериализуемым.

### Validation layer

Отвечает за ошибки размеров, ошибки секций, ошибки зон, warning-состояния и блокировку заявки при критичных ошибках.

### Visual layer

Отвечает за визуализацию модели, камеры, выбранные зоны, material preview и fallback при недоступности 3D.

### Pricing boundary

Стоимость должна считаться через единый pricing engine. Интерфейс конструктора не должен иметь альтернативный калькулятор.

### Checkout boundary

Checkout должен использовать готовую валидную конфигурацию. Изменения order flow запрещены без отдельного задания.

## Запрещенные смешения

Нельзя:

- считать стоимость вручную внутри React-компонентов;
- создавать отдельную pricing-логику для preview;
- отправлять заявку из визуального слоя;
- хранить персональные данные в localStorage;
- смешивать production warnings с пользовательскими ошибками без адаптации текста;
- добавлять новые API-контракты без contract-documentation.

## Ближайший безопасный принцип развития

Перед редизайном или 3D-пересборкой нужно завершить architecture docs, protected zones, testing strategy, CI stabilization и development readiness task.
