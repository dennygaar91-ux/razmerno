# Frontend final map — конструктор Размерно

Документ фиксирует текущее состояние frontend-части конструктора после UX/UI-полировки. Backend временно не трогаем.

## Общая стадия

```txt
Frontend конструктора — 88–90%
```

Это уже не сырой прототип, а рабочий pre-MVP frontend. Основной функциональный сценарий собран:

1. Пользователь открывает конструктор.
2. Задаёт размеры шкафа.
3. Настраивает секции.
4. Выбирает наполнение.
5. Выбирает материалы и фурнитуру.
6. Видит предварительную стоимость.
7. Сохраняет проект или отправляет его в корзину.
8. Оформляет заявку через checkout drawer.

## Что уже хорошо

### 1. Основная структура

- используется трёхколоночная логика: настройки / viewer / стоимость;
- сохранён принцип 25% / 50% / 25%;
- страница похожа на продуктовый интерфейс, а не на технический тест;
- основные компоненты уже разделены.

### 2. Левая панель

- есть пошаговый сценарий;
- есть подсказки внутри шагов;
- добавлены disabled-состояния;
- активная секция стала понятнее;
- есть presets наполнения;
- есть копирование и применение наполнения.

### 3. Viewer

- viewer разделён на компоненты;
- есть scene-контракт для будущего Three.js;
- есть quick actions;
- есть карта секций;
- есть подписи размеров;
- есть связь активной секции с левой панелью.

### 4. Правая панель

- стоимость стала главным элементом;
- смета стала компактнее;
- есть статус проекта;
- есть CTA в корзину;
- предупреждения не выглядят как критические ошибки.

### 5. Checkout

- drawer разделён на понятные шаги;
- есть поля клиента;
- есть ошибки валидации;
- есть success-state;
- честно объясняется, что оплата будет после проверки проекта технологом.

### 6. Сохранение

- есть localStorage;
- есть projectId;
- есть metadata updatedAt;
- есть автосохранение;
- есть подтверждение перед очисткой;
- есть статусы сохранения.

## Основные риски

### 1. Визуальная плотность на laptop

Главный риск — разрешения 1366×768 и 1440×900. Интерфейс насыщенный, поэтому после живой проверки могут понадобиться точечные сокращения:

- убрать вторичный текст;
- уменьшить высоты карточек;
- упростить right summary;
- сократить quick actions.

### 2. CSS-слои

Сейчас полировка подключена несколькими CSS-файлами:

```txt
ConstructorConfigPolish.css
ConstructorViewerPolish.css
ConstructorCheckoutPolish.css
ConstructorDesktopPass.css
ConstructorMaterialsPolish.css
ConstructorProjectSafety.css
ConstructorStatusPolish.css
```

Это удобно для итераций, но позже лучше собрать стили по компонентам или хотя бы упорядочить импорт, чтобы избежать конфликтов.

### 3. Viewer остаётся mockup

Центральный шкаф пока CSS-mockup. Он подходит для UX-проверки, но для финального продукта нужен Three.js или качественный render-layer.

### 4. Материалы пока демонстрационные

Материалы улучшены UX-метаданными, но для production нужны реальные справочники:

- производитель;
- артикул;
- декор;
- толщина;
- цена;
- текстура;
- кромка;
- доступность.

## Что осталось до 95–100%

### До 95%

1. Проверить сайт по скриншотам на desktop/laptop.
2. Исправить визуальные разъезды.
3. Упростить слишком плотные места.
4. Проверить весь сценарий: размеры → наполнение → материалы → корзина.
5. Убедиться, что drawer не ломает страницу.
6. Проверить localStorage: автосохранение, загрузка, очистка.

### До 100%

1. Подключить реальный Three.js viewer.
2. Заменить demo-материалы на реальный каталог.
3. Добавить production-валидацию правил конструктора.
4. Довести адаптив tablet/mobile.
5. Провести полный UX-тест на пользователе без мебельного опыта.
