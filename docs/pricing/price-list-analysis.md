# Анализ прайс-листа для pricing-engine

Источник: `Прайс-лист для дилеров до 01.04.26.xlsx`

Правило пользователя: при подготовке базы данных для каждого материала, услуги и прочих позиций увеличивать стоимость на **30%**.

## Листы прайс-листа

| Лист | Диапазон | Что содержит | Особенность нормализации |
|---|---:|---|---|
| `Kronospan` | `A1:I152` | ЛДСП/декоры Kronospan | Цены разложены по толщинам `10/16/25 мм`; одна строка может давать несколько price-items |
| `Кромка` | `A1:J51` | Кромка Kronospan/Egger/Eterno/AGT | На листе две таблицы: слева и справа; есть отдельные цены для однотонных/древесных |
| `Eterno` | `A1:B66` | Материалы Eterno 18 мм | Цена за 1 кв.м.; артикул зашит в названии |
| `Egger` | `A1:Y154` | ЛДСП Egger по декорам/структурам/толщинам | Цены по толщине `8/10/16/18/22/25/28/38 мм`; рядом есть статус `●/○` |
| `AGT` | `A1:D129` | AGT панели/фасадные материалы | Цена за кв.м.; артикул и название отдельными колонками |
| `Кедр столешницы` | `A1:D50` | Столешницы Кедр | Цена за штуку; размер зашит в названии |
| `Услуги` | `A1:C14` | Производственные услуги | Не все цены числовые, например “по цене кромки” |

## Правило цены

Для каждой числовой цены:

```txt
retail_price = source_price * 1.30
```

В БД нужно хранить обе цены:

- `source_price` — цена из прайс-листа;
- `markup_multiplier` — `1.30`;
- `retail_price` — рассчитанная цена для использования в калькуляторе.

## Рекомендованная модель БД

Основная таблица: `price_items`.

Каждая строка — одна конкретная ценовая позиция:

- материал + толщина;
- кромка + размер + категория;
- услуга;
- столешница + размер + категория;
- панель/фасадный материал.

Это удобнее для калькулятора, чем хранить Excel-структуру “как есть”.

## Классификация item_type

| item_type | Что входит |
|---|---|
| `board` | ЛДСП/плитные материалы Kronospan/Egger/Eterno |
| `edge` | кромка ABS/PVC |
| `panel` | AGT фасадные панели |
| `worktop` | столешницы Кедр |
| `service` | распил, кромление, фрезеровка, еврозапил и прочие услуги |

## Что важно для следующих задач

1. Импорт должен пропускать пустые цены.
2. Нечисловые цены нужно сохранять как `source_note`, но не использовать в расчёте автоматически.
3. Для Egger/Kronospan каждая толщина должна стать отдельной строкой.
4. Для `Кромка` нужно разобрать две таблицы на одном листе.
5. Для расчёта MVP шкафа в первую очередь нужны:
   - ЛДСП 16 мм;
   - кромка корпус 0.8/1 мм;
   - кромка фасады 2 мм;
   - услуги: распил, кромление, присадка, упаковка.
